# 对照 Jira 的页面完善清单

对照 Jira Cloud 软件空间的用户说明，和现在这套项目协作前端。日期：2026-10-02。

依据的是 Atlassian 支持文档里软件空间日常会用到的页面，不是整份管理员手册：

- [摘要 Summary](https://support.atlassian.com/jira-software-cloud/docs/what-is-the-summary-view/)
- [看板与快速筛选](https://support.atlassian.com/jira-software-cloud/docs/show-or-hide-issues-on-your-board/)
- [清单 List](https://support.atlassian.com/jira-software-cloud/docs/what-is-the-list-view/)
- [时间线 Timeline](https://support.atlassian.com/jira-software-cloud/docs/create-manage-and-visualize-work-on-the-timeline/)
- [打开事项](https://support.atlassian.com/jira-software-cloud/docs/view-a-work-item/)
- [报告目录](https://support.atlassian.com/jira-software-cloud/docs/track-and-analyze-your-teams-work-with-reports/)：燃尽、燃起、速率、版本、史诗、累积流
- 看板洞察：迭代进度、范围变化、卡住的事项

不建议照搬、这次也不列入：站点管理、权限方案、自动化、JQL、代码/部署、应用市场、日历视图、多项目 Plans。测试、追溯、发布门禁是这套产品自己的，Jira 软件空间没有对等页，保持现状。

状态：

- **有**：主路径已经接近。
- **薄**：页面在，但 Jira 里天天用的交互还没有。
- **不做**：超出当前产品范围。

## 1. 模块对照

| Jira 页面 | 现在 | 已经有 | 还差 |
|---|---|---|---|
| 摘要 | 仪表盘，薄 | 当前迭代完成数、未关缺陷、失败用例、待审工时、我的未完成、需求状态和严重度条 | 近 7 天完成/更新/新建/即将到期、最近动态、按史诗看进度、摘要筛选 |
| 看板 | 看板，薄 | 按列拖动并走状态机、切换看板和迭代、只看我的、类型、已取消 | 按人多选、标签筛选、列内排序、在制品上限、卡片上的编号/点数/父事项、卡住提示 |
| 待办 | 待办，薄 | 拖进迭代、改排期、完成迭代时未完成退回未排期 | 待办和迭代内上下排序、按史诗分组、行内新建、故事点合计、迭代目标 |
| 清单 | 事项，薄 | 关键字、类型、只看我的、隐藏已完成，点行打开 | 表头排序、行内改负责人/状态/点数、按迭代或父事项分组、显示更多列 |
| 时间线 | 甘特图，薄 | 拖动改计划、按依赖类型连线、违反时顺延、基线细条 | 按史诗分组、版本竖线、在图上新建依赖、进度开关、只看某一层 |
| 事项 | 大弹层，有 | 标题、描述、流转、属性、子事项、评论、动态 | 上下条切换、克隆、关注、标签、到期日、在事项里记工时、关联事项不只父子 |
| 发布 / 版本 | 版本，有 | 范围加减、环境、草稿到发布、门禁和快照 | 版本完成进度条、按速率推算完成日。发布门禁保留，Jira 没有 |
| 报告 | 统计，薄 | 类型、状态、负责人、迭代、严重度、近四周完成次数 | 迭代燃尽（理想线/剩余）、跨迭代速率、版本剩余。累积流先不做 |
| 工时 | 工时，有 | 登记、待审可改、审批、按人/任务/日期汇总、导出 | 事项上直接记工时、剩余估算对比原估算 |
| 通知 | 通知，有 | 未读/全部、提及/事项/迭代/发布，点进事项再返回筛选还在 | 关注事项后才收到更新。现在没有关注 |
| 项目设置 | 设置，薄 | 名称、简介、负责人、成员 | 卡片要显示哪些字段。工作流设计器继续不做 |

## 2. 功能

这些是页面里缺的数据或动作，不是新开路由。

| 页面 | 要补的功能 |
|---|---|
| 看板 | 列上的在制品上限。超过时列头变提示，不拦拖动。卡片增加编号、故事点、父事项 |
| 待办 | 记住事项在迭代内和未排期里的顺序。按父需求折成一组。每组显示点数合计 |
| 事项 | 克隆一条未开始的副本。标签。到期日。关注后，状态和评论写入通知。在弹层里记一条工时 |
| 清单 | 可选列：优先级、状态、负责人、迭代、点数、更新时间。点表头排序 |
| 甘特图 | 按父需求分组。版本的计划发布日画成竖线。两条事项之间补一条依赖 |
| 仪表盘 | 近 7 天：完成、更新、新建、未来 7 天到期。史诗下子事项的完成比例。最近动态，点得进事项 |
| 统计 | 当前迭代燃尽：按天的剩余点数，和一条理想直线。各已完成迭代的完成点数，当作速率。版本范围内未完成点数 |
| 工时 | 原估算、已记、剩余。剩余手填，不自动用原估算去减 |

到期日、标签、关注、排序、在制品上限都是事项或看板上的新字段，只存在这台浏览器里。

## 3. 交互

| 现在 | Jira 的做法 | 建议改成 |
|---|---|---|
| 看板筛选是一排下拉 | 筛选条：人头多选、类型、标签，可收成按钮 | 看板顶部一条筛选。人头可多选，「只看我的」留着 |
| 列内拖动只改状态 | 同一列上下拖是排序；右键可置顶或置底 | 同列上下拖改顺序。跨列仍只走允许的状态 |
| 待办只能拖进别的迭代 | 待办里上下拖决定下一轮先做哪条 | 同一组里上下拖排序 |
| 清单点整行才能改 | 清单里直接改负责人、状态、点数 | 这些三列可在行内改。标题仍点开弹层 |
| 事项只能关了再点下一条 | `J` / `K` 或上一条、下一条 | 弹层里上一张、下一张，沿当前清单顺序 |
| 甘特依赖要去依赖页添加 | 时间线上两条之间拉出依赖 | 甘特上从一条拖到另一条，默认完成-开始，可改类型 |
| 报告是静态汇总 | 燃尽随着迭代里的完成和范围变化一起看 | 燃尽用现有日期和点数算，不接图表库。范围变化用一句话写在图下 |
| 记工时要离开事项 | 事项详情里就能记时间 | 弹层属性区加「记一笔」，写入现在的工时页 |

不做：右键菜单大全、保存多套自定义筛选、把筛选做成 JQL。

## 4. 界面

不改整体成 Jira 的蓝色皮肤。沿用现在的飞书式表面、3px 圆角和现有字号。只改这几处看不清或不好扫的地方。

| 位置 | 现在 | 改成 |
|---|---|---|
| 看板卡片 | 标题、类型、优先级、头像 | 第一行编号加标题。底部：类型、优先级、点数、头像。有父事项时在标题上加一小条父编号 |
| 看板列 | 列名和卡片 | 列头加上数量，设了上限再显示 `3/5`。超出用危险色，不另做角标 |
| 筛选 | 各页样式不统一，有的下拉有的按钮 | 看板、清单、待办都用同一条筛选：输入框加可切换的小按钮 |
| 清单 | 一行一个大按钮 | 表格式。表头可点。行高保持现在的紧凑行，不做成卡片 |
| 仪表盘 | 四格数字在前 | 上面四格改成近 7 天。下面左动态、右史诗进度。现有缺陷和工时数字收进第二行 |
| 燃尽 | 没有 | 统计页一块。灰线理想、主色线剩余。没有历史点数时，用「当天剩余」说明，不画假曲线 |
| 甘特图 | 平铺 | 父需求做组头，子事项缩进。版本日是一条浅竖线，和今天的红线区分开 |
| 空状态 | 各页一句说明 | 保持一句。不加重插画 |

## 5. 建议先做

仍不新开页面。建议顺序：

1. 看板：筛选条、卡片信息、列内排序、在制品上限。
2. 待办：组内排序、按父需求分组、点数合计。
3. 事项：上一张下一张、克隆、标签、到期日、弹层里记工时。
4. 清单：表头排序、行内改三个字段。
5. 仪表盘和统计：近 7 天、史诗进度、迭代燃尽、速率。
6. 甘特图：按父需求分组、版本竖线、在图上拉依赖。
