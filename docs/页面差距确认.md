## 4. 建议补的内容

只列项目里还缺的交互。不新开系统管理。

### 页面

这些不建议再拆成原项目那么多路由。缺的是页内能力，不是入口。

| 页面 | 要补什么 |
|---|---|
| 甘特图 | 拖动时守住依赖：完成-开始不能把后置拉到前置结束之前；滞后天数算进去；四种依赖用不同端点连线。拖一条时，被挡住的后置一起后移或明确拒绝。可选：基线对比 |
| 依赖 | 依赖图。点一条依赖看出影响哪些后置。和甘特用同一套规则 |
| 追溯 | 影响范围（改这条需求会碰到哪些任务、用例、缺陷、版本）。证据矩阵：需求 × 用例 × 最近结果。导出带上这段 |
| 版本 | 发布单详情：提交、通过/退回、发布门禁（未关缺陷、失败用例）、豁免要填原因、发布快照（当时的范围和结果，之后不再变） |
| 测试 | 用例详情（前置、步骤、期望、关联需求）。套件里加减用例。复制、归档。运行报告固定成当时的计数，不随后来改用例而变 |
| 工时 | 改正一条待审记录。按人、按任务、按日期汇总。导出沿用现在的 CSV，把汇总一起带上 |
| 仪表盘 / 统计 | 需求类型和状态分布、缺陷严重度、近几周完成数。用现有数据算，不另做仪表盘列表 |
| 项目设置 | 成员角色只做到「负责人 / 成员」。通知开关如果要做，只做本机偏好 |
| 分配 | 某人名下展开时，能看到未完成事项的最近一条流转和已记工时 |
| 通知 | 未读 / 全部。点进事项后回来仍停在通知 |

不单开这些页：需求创建、任务创建、缺陷创建、工时创建、用例创建、发布草稿、看板列表。继续用现在的页面和弹窗。

### 组件

| 组件 | 用在哪 |
|---|---|
| 依赖连线规则 | 甘特和依赖页共用。现在甘特线不区分开始/结束端点，也不算滞后 |
| 依赖图 | 依赖页 |
| 影响范围、证据矩阵 | 追溯页 |
| 发布详情 | 审批、门禁、豁免原因、快照。版本页里打开，不另做一整套系统页 |
| 用例详情 | 测试页里打开 |
| 套件成员 | 测试页 |
| 工时汇总 | 工时页，三块：人、任务、日期 |
| 分布条 | 统计和仪表盘。沿用现在的计量条，不上图表库 |

### 交互

| 交互 | 现在 | 要改成 |
|---|---|---|
| 甘特拖动 | 只改被拖的那条计划 | 违反完成-开始时拒绝，或把后置顺延。松手后和依赖页的冲突提示一致 |
| 依赖连线 | 一律从前置右端到后置左端 | 完成-开始、开始-开始、完成-完成、开始-完成各连各的端 |
| 发布 | 草稿直接点发布 | 先看门禁。不通过就不能发，除非填写豁免原因 |
| 发布之后 | 范围仍是活数据 | 快照冻住当时的事项和测试结果 |
| 用例 | 步骤嵌在列表里 | 详情里改步骤；套件勾选用例；归档后默认列表不显示 |
| 运行报告 | 打开时现算 | 完成后把计数存进这次运行 |
| 工时 | 只能新增和审批 | 待审可改；已通过/已驳回不可改，要改就另记一条 |
| 事项创建/编辑 | 弹窗 | 保持。不恢复独立编辑页 |
